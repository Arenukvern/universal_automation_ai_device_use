## Branches and checkouts

**Q: Should I use git worktrees on this repo?**  
A: **No.** Use a single checkout and feature branches (`git checkout -b cursor/...` off current `main`). Rationale: [Design FAQ — worktrees](/DESIGN_FAQ#release-train-and-workspace-policy).

**Q: What do I run before opening a PR?**  
A: `dart analyze` on the packages in [steward.yaml](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/steward.yaml) `stewardship.quality.validate`, `dart run tool/sync_workspace_pub_constraints.dart --check`, and any contract scripts your change touches under `tool/contracts/`. CI runs the same analyze list.

## Release train (contributors)

**Q: How do package versions get bumped?**  
A: Add a changeset in your feature PR: `dart run dart_changesets@^1.0.2 add` (or author `.changesets/*.md` with front matter `'package_name': patch|minor|major`). After merge to `main`, [`release.yml`](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/.github/workflows/release.yml) opens/updates **`changesets/version-packages`**. Merge that version PR when CI is green — tags and [`publish.yml`](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/.github/workflows/publish.yml) legs follow automatically. Do not hand-edit `version:` or `CHANGELOG.md` on releasable packages ([RELEASING.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/RELEASING.md)).

**Q: What runs on the version-packages PR?**  
A: Same `Validate` jobs as other PRs plus blocking co-release/drift/audit with `--release-pr`, and strict `dart pub publish --dry-run` for every publishable package (warnings exit **65**). Also `dart run tool/sync_workspace_pub_constraints.dart --check`.

**Q: How do I refresh sibling `^` constraints locally?**  
A: `dart run tool/sync_workspace_pub_constraints.dart --write` (or `--check` in CI). Caret raises only when pub rules require it — [Design FAQ — caret floor](/DESIGN_FAQ#release-train-and-workspace-policy).

**Q: How do I install toolkit CLI without `dart pub global`?**  
A: Download platform archives from the toolkit GitHub release (`universal_automation_toolkit-v*`) per [RELEASING.md § binaries](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/RELEASING.md#toolkit-github-release-binaries-no-dart-install) or use `./install.sh` at repo root.

## Browser (CDP)

**Q: How do I point UA at Chrome for browser automation?**  
A: Start Chrome **yourself** with remote debugging, then attach — UA does not launch the browser. Use a CDP base URI (e.g. `http://127.0.0.1:9222`) with `CdpBrowserSession.attach` or toolkit `cdp(...)` session wiring ([CDP README](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/pkgs/universal_browser_cdp/README.md)).

## Browser (WebDriver)

**Q: How do I point UA at chromedriver, geckodriver, or safaridriver?**  
A: Start the **WebDriver HTTP server yourself** — UA attaches to the base URL; it does not replace your browser supervisor (same lifecycle rule as CDP). Examples: `chromedriver --port=9515`, `geckodriver`, or `safaridriver -p 7051` (Safari needs one-time `safaridriver --enable`). Toolkit:

```bash
universal-automation serve --webdriver http://127.0.0.1:9515
# or
export UNIVERSAL_AUTOMATION_WEBDRIVER=http://127.0.0.1:7051
universal-automation serve --webdriver "$UNIVERSAL_AUTOMATION_WEBDRIVER"
```

The registry calls `WebDriverClient(endpoint).newSession()` on attach ([toolkit registry](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/pkgs/universal_automation_toolkit/lib/src/runner/registry.dart)). With only webdriver configured, MCP/CLI `act`, `screenshot`, and related `automation_*` verbs use that tier; when you configured multiple transports, pass per-call `transport: "webdriver"` on MCP tools (`cdp | webdriver | osAccessibility`).

**Q: What works on the WebDriver tier in MCP/CLI?**  
A: Classic W3C commands: navigate, find/click/type, screenshots, W3C pointer actions — same honest limits as [Design FAQ — WebDriver](/DESIGN_FAQ#platform-tiers-honest-today). **`automation_observe` / semantic tree paths refuse** because `WebDriverDriver.snapshot()` refuses (no a11y tree on classic WebDriver). For Chromium page automation with a tree, use CDP attach instead. Library users can call `WebDriverClient.bidi()` when `webSocketUrl` was advertised at session creation.

## Packages & pub.dev

**Q: Which packages are on pub.dev?**  
A: Core contracts, semantics, conformance, toolkit, browser drivers, screencast, WebRTC helpers, OS drivers, capture packages, and **`universal_tooling_runtime`** (0.2.0+) are published from this repo. **`universal_lexicon`** lives in [`dart_flutter_packages`](https://github.com/xsoulspace/dart_flutter_packages/tree/main/pkgs/universal_lexicon) — path/git pin that checkout (or pub.dev when DFP publishes).

**Q: How do I depend on a package while hacking this monorepo?**  
A: In-repo packages resolve via the root `workspace:` entry — no override needed for `pkgs/*`. For sibling checkouts (xsoulspace, another app repo), copy `pubspec_overrides.yaml.example` to gitignored `pubspec_overrides.yaml` or run `./tool/overrides.sh write` (see [CONTRIBUTING.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/CONTRIBUTING.md)). External apps should use pub.dev version constraints when available.

**Q: What is the publish order?**  
A: [ADR 0001](/decisions/0001_drivers_into_ua_private_oss_ready) — contracts and semantics before drivers and toolkit.

## Captures

**Q: How do I capture the whole page, not just the viewport?**  
A: `automation_screenshot {fullPage: true}` (CDP tier), `screenshot --full-page`, or `shot('/tmp/x.png', fullPage: true)` in a plan. The macOS tier refuses it — a native window has no scroll extent — and the refusal names the route out.

**Q: How do I keep a screenshot small enough for a vision model?**  
A: `maxPx` caps the long side (`automation_screenshot {maxPx: 1024}`). The image is scaled **at capture time** by the browser, so this is a budget rather than a fidelity loss: a model downsamples a large image to its own input ceiling anyway, so capping there keeps every pixel the model would have seen. A cap _below_ that ceiling does discard detail — the cap is your explicit choice.

**Q: Which tab does it capture when the browser has several open?**  
A: Name it: `targetId` / `targetUrl` / `targetTitle` (MCP), `--target-id` / `--target-url` / `--target-title` (CLI), or in a plan the session URI carries it (`http://127.0.0.1:9222#targetUrl=/checkout`). Attaching to "the first page" is a guess, so an ambiguous or empty match refuses with the candidate list instead.

**Q: Can I get JPEG instead of PNG?**  
A: `format: "jpeg"` with `quality` (1..100) — CDP and macOS tiers, natively. The W3C WebDriver standard returns PNG only, so that tier refuses and names the route out.

**Q: The macOS capture says Screen Recording is required. Now what?**  
A: `automation_request_consent {kind: "screenRecording"}` asks the OS (the system prompt appears) and reports whether the grant is now held. A capture never raises the prompt by itself. See [ADR 0005](/decisions/0005_capture_options_target_selection_and_os_consent).

## Background browsers (no CDP)

**Q: How do I drive a browser form while another app stays focused?**  
A: On macOS, anchor with `app: {bundleId|pid|name}`, use `automation_observe` (web-first walk), `automation_preview` for frames, and semantic `setValue`/`click` or window-local `clickAt` with `windowId`. See ADR 0007 / family ADR 0065.

**Q: How do I run the Codex-style computer loop (screenshot → pixel click) without CDP?**  
A: `automation_computer` on `serve --os`: `bind` → `screenshot` (image block + `width`/`height`/`scale`) → `click`/`type` in image coordinates. Grants: `automation_request_consent` for `accessibility` and `screenRecording` (`automationComputerUseOsKinds` in `xsoulspace_permission_core`). Rebuild after native changes: `./plugin/install.sh`. Plumbing probe: `dart run example/computer_use_parity_probe.dart`. See ADR 0008 / family ADR 0066.
