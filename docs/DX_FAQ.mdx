## Packages & pub.dev

**Q: Which packages are on pub.dev?**  
A: Core contracts, semantics, conformance, toolkit, browser drivers, screencast, WebRTC helpers, OS drivers, capture packages, and **`universal_tooling_runtime`** (0.2.0+) are published from this repo. **`universal_lexicon`** lives in [`dart_flutter_packages`](https://github.com/xsoulspace/dart_flutter_packages/tree/main/pkgs/universal_lexicon) — path/git pin that checkout (or pub.dev when DFP publishes).

**Q: How do I depend on a package while hacking this monorepo?**  
A: In-repo packages resolve via the root `workspace:` entry — no override needed for `pkgs/*`. For sibling checkouts (xsoulspace, another app repo), copy `pubspec_overrides.yaml.example` to gitignored `pubspec_overrides.yaml` or run `./tool/overrides.sh write` (see [CONTRIBUTING.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/CONTRIBUTING.md)). External apps should use pub.dev version constraints when available.

**Q: What is the publish order?**  
A: [ADR 0001](/decisions/0001_drivers_into_ua_private_oss_ready) — contracts and semantics before drivers and toolkit.

## Captures

**Q: How do I capture the whole page, not just the viewport?**  
A: `automation_screenshot {fullPage: true}` (CDP tier), `screenshot --full-page`, or `shot('/tmp/x.png', fullPage: true)` in a plan. The macOS tier refuses it — a native window has no scroll extent — and the refusal names the route out.

**Q: How do I keep a screenshot small enough for a vision model?**  
A: `maxPx` caps the long side (`automation_screenshot {maxPx: 1024}`). The image is scaled **at capture time** by the browser, so this is a budget rather than a fidelity loss: a model downsamples a large image to its own input ceiling anyway, so capping there keeps every pixel the model would have seen. A cap _below_ that ceiling does discard detail — the cap is your explicit choice.

**Q: Which tab does it capture when the browser has several open?**  
A: Name it: `targetId` / `targetUrl` / `targetTitle` (MCP), `--target-id` / `--target-url` / `--target-title` (CLI), or in a plan the session URI carries it (`http://127.0.0.1:9222#targetUrl=/checkout`). Attaching to "the first page" is a guess, so an ambiguous or empty match refuses with the candidate list instead.

**Q: Can I get JPEG instead of PNG?**  
A: `format: "jpeg"` with `quality` (1..100) — CDP and macOS tiers, natively. The W3C WebDriver standard returns PNG only, so that tier refuses and names the route out.

**Q: The macOS capture says Screen Recording is required. Now what?**  
A: `automation_request_consent {kind: "screenRecording"}` asks the OS (the system prompt appears) and reports whether the grant is now held. A capture never raises the prompt by itself. See [ADR 0005](/decisions/0005_capture_options_target_selection_and_os_consent).

## Background browsers (no CDP)

**Q: How do I drive a browser form while another app stays focused?**  
A: On macOS, anchor with `app: {bundleId|pid|name}`, use `automation_observe` (web-first walk), `automation_preview` for frames, and semantic `setValue`/`click` or window-local `clickAt` with `windowId`. See ADR 0007 / family ADR 0065.

**Q: How do I run the Codex-style computer loop (screenshot → pixel click) without CDP?**  
A: `automation_computer` on `serve --os`: `bind` → `screenshot` (image block + `width`/`height`/`scale`) → `click`/`type` in image coordinates. Grants: `automation_request_consent` for `accessibility` and `screenRecording` (`automationComputerUseOsKinds` in `xsoulspace_permission_core`). Rebuild after native changes: `./plugin/install.sh`. Plumbing probe: `dart run example/computer_use_parity_probe.dart`. See ADR 0008 / family ADR 0066.
