# Universal automation device use — North Star

**Status:** active · **Audience:** humans and agents

## What we are

**Universal automation device use** is a **composable observe / act / verify
family** for real devices and apps: Dart contracts (`universal_automation_*`),
platform drivers (OS, browser, capture, WebRTC), lexicon packs in
[`dart_flutter_packages`](https://github.com/xsoulspace/dart_flutter_packages/tree/main/pkgs/universal_lexicon),
and an agent-facing
**MCP + CLI toolkit** (`universal_automation_toolkit`) — **one MCP server** with
platform **adapters** behind a single observe / act / capture surface (ADR 0009).

The north star is an **optimistic, humane** future where **people and AI agents**
can work with desktop, mobile, browser, and future tiers through the same
**declarative, compositional** surface — with **consent, receipts, and honest
proof**, not opaque takeover of user machines.

Innovation here is **legible automation**: smaller, inspectable routes for the
next human or agent. That aligns with the wider automation chain in
[`mcp_flutter`](https://github.com/Arenukvern/mcp_flutter) (Flutter app harness)
while this repo owns **cross-tier contracts and drivers**.

Stewardship follows the
[`mcp_flutter`](https://github.com/Arenukvern/mcp_flutter) /
[`skill_steward`](https://github.com/Arenukvern/skill_steward) OSS pattern:
charter, ADRs, `steward.yaml` validation, CONTRIBUTING, and SECURITY. Broader
author principles: [Principles at work (credo)](https://dev.to/arenukvern/my-principles-at-work-credo-182c).

We are **not** a generic domain tutorial catalog. We are **not** the Flutter
in-app runtime harness (see `mcp_flutter`). We are **not** claiming every OS
driver tier is production-ready without platform-specific proof.

## Current proof

| Status | Evidence | Do not overclaim |
| --- | --- | --- |
| Proven | Published-style package layout, MIT licenses, `dart analyze` gate in CI (`steward.yaml`), conformance package, toolkit CLI/MCP, CDP attach to user-started Chrome | Unattended production agent control of end-user devices |
| Emerging | macOS AX/CGEvent **preview** (ad-hoc signed release binaries; TCC re-grant after updates), Linux AT-SPI read/semantic click, plugin bundle | Every OS tier production-hardened; mobile adapters shipped |
| Roadmap / blocked | Android/iOS factory slots ([ADR 0009](/decisions/0009_one_mcp_server_with_adapters)), Windows UIA sidecar binary | Marketing mobile or Windows desktop use as available today |
| Not owned | `universal_storage_*` (sibling repo), Flutter JIT debug harness (consumer + `mcp_flutter`) | Replacing OS security prompts or consent models |

## Platform tiers (honest today)

| Tier | Status | What to expect |
| --- | --- | --- |
| **macOS** | Preview | `universal_driver_macos` + toolkit `serve --os`; release binaries are **ad-hoc signed**; TCC (Accessibility, Screen Recording) **re-grant after each toolkit update** ([RELEASING.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/RELEASING.md#macos-code-signing-optional-not-configured-yet)). |
| **Browser (CDP)** | Supported attach | Attach to **existing** Chrome over CDP — UA does not launch the browser ([CDP README](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/pkgs/universal_browser_cdp/README.md)). |
| **Linux** | Narrow | AT-SPI **read + semantic click** only — no keyboard synthesis ladder ([driver README](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/pkgs/universal_driver_linux/README.md)). |
| **Windows** | Not shipped | UIA Rust sidecar is **not** a release artifact; toolkit refuses without it ([Windows driver README](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/pkgs/universal_driver_windows/README.md)). |
| **Android / iOS** | Roadmap | Adapter slots and `oka_devices` handoff only — no shipped mobile drivers in this repo ([ADR 0009](/decisions/0009_one_mcp_server_with_adapters)). |

Standing **why** for each tier: [Design FAQ](/DESIGN_FAQ#platform-tiers-honest-today). Operational setup: [DX FAQ](/DX_FAQ).

## What we own

| Own | Do not own |
| --- | --- |
| `AutomationDriver` contracts, semantics, conformance | End-user app product logic in consumer repos |
| OS/browser/capture/WebRTC driver packages | Universal storage product family |
| Toolkit: plans, runner, one MCP server + adapters, plugin/skills | Official MCP registry approval (submission is separate); never per-platform MCP servers |
| ADRs, SECURITY, consent-gated composition patterns | Silent bypass of accessibility / screen-recording consent |
| Release/changelog intent per package (migrating to **Dart Changesets**; Release Please until that PR lands) | Hidden automation without receipts or fail-closed refusal |

## North star impact habit

Before durable structural changes, classify `north_star_impact`: `none`, `applies`,
`clarifies`, `sub_star`, `amends`, or `conflicts`. `amends` / `conflicts` require
ADR work before the repo center moves. See [AGENTS.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/AGENTS.md).

## Boundaries (non-negotiable)

- Behavior SSOT is **code and schemas**; docs link inward.
- **Charter** → this document (`docs/NORTH_STAR.mdx`, published via [docs.json](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/docs.json)); [AGENTS.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/AGENTS.md) is the agent map only.
- New strategic **why** → ADR in [docs/decisions/](https://github.com/Arenukvern/universal_automation_ai_device_use/tree/main/docs/decisions).
- Standing operational **why** → [Design FAQ](/DESIGN_FAQ).
- Operational **how** → [DX FAQ](/DX_FAQ).
- Domain tutorials and app-specific harnesses stay in their product repos.
- No public issue for unpatched security vulnerabilities ([SECURITY.md](https://github.com/Arenukvern/universal_automation_ai_device_use/blob/main/SECURITY.md)).
- Agent/CI checkouts: **no git worktrees** — feature branches on a single clone (see [Design FAQ](/DESIGN_FAQ#release-train-and-workspace-policy)).

## Success looks like

- Humans and agents share one compositional automation vocabulary across device classes.
- MCP clients configure **one** Universal Automation server; new tiers ship as adapter packages, not new server products (ADR 0009).
- Drivers and toolkit **refuse** rather than guess when consent or capability is missing.
- Claims stay proportional to evidence (validation gate, per-package tests, platform proofs).
- Fresh contributors find charter, ADRs, and native validation without hidden local paths.
- Packages publish in dependency order with legible changelogs ([ADR 0001](/decisions/0001_drivers_into_ua_private_oss_ready)).
